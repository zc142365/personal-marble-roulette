## 왜 만들었나

**필요해서 만들었다.**

원본은 브라우저 탭 하나에서 혼자 돌리는 앱이라, 여러 명이 같은 추첨을 같이 보려면
한 화면 앞에 둘러앉거나 화면 공유를 걸어야 했다. 각자 자기 기기에서 같은 경기를 보고
진행자만 시작할 수 있으면 좋겠다 싶었고, 마침 그런 게 없어서 직접 만들었다.
쓰다 보니 남도 쓸 수 있겠다 싶어 정리해서 공개해 둔 것이다.

## 수익을 추구하지 않는다

이 저장소는 **어떤 방식으로도 수익을 추구하지 않는다.**

- 후원·기부 링크 없음
- 광고 없음
- 결제·유료 기능·구독 없음
- 상점 연동 없음
- 유료 배포 없음
- **사용자 추적·분석 없음** (외부로 나가는 요청이 하나도 없다)

원본에 들어있던 상점 버튼, 유료 상품 홍보 공지, 후원(Buy me a coffee) 관련 코드,
상점 API 연동은 **전부 제거**했다 ([삭제한 것](#수정-범위) 참고).
개인적으로 필요해서 만든 것이고, 앞으로도 이걸로 돈을 벌 생각이 없다.

후원할 마음이 있다면 이 저장소가 아니라 **원저작자 [LazyGyu](https://lazygyu.net) 님께**
해주시기 바란다. 이 프로젝트의 본체를 만든 사람은 그쪽이다.

## 무엇이 달라졌나 (이 저장소에서 만든 것)

원본은 브라우저 탭 하나에서 혼자 돌리는 앱이었다. 여기에 붙인 것:

1. **어디서든 띄울 수 있는 호스팅 서버** — `node server.mjs` 하나로 정적 파일 서빙 + 중계.
   외부 의존성 없음 (Node 내장 모듈만 사용).
2. **관리자 / 참여자·관전자 분리** — 관리자만 참가자 명단·맵·당첨 순위를 정하고 시작할 수 있다.
   서버가 관리자 키로 검증하므로 관전자가 브라우저 콘솔을 열어도 남의 화면은 못 건드린다.
3. **모두가 같은 화면** — 화면을 스트리밍하지 않는다. 관리자가 **seed 하나**를 뿌리면
   모든 접속자가 자기 기기에서 같은 물리 시뮬레이션을 돌린다. 그래서 인원이 몇 명이든
   트래픽은 거의 0이고, 각자 자기 화면 해상도로 선명하게 본다.
4. **PWA / exe** — 웹으로 접속해도 되고, 폰·PC에 앱으로 설치해도 되고,
   관리자는 설치 과정 없는 exe 하나로 서버까지 같이 띄울 수 있다.

### 같은 화면을 보장하는 방법

| | 흔한 방법 | 여기서 쓴 방법 |
|---|---|---|
| 전송 내용 | 매 프레임 좌표 또는 영상 | 시작할 때 seed + 설정 1회 |
| 서버 부하 | 인원수에 비례 | 인원수와 무관 |
| 화질 | 스트리밍 화질 | 각자 원본 화질 |

대신 시뮬레이션이 **완전히 결정론적**이어야 한다. 그래서 아래를 손봤다.

- 시뮬레이션용 난수를 시드 기반 PRNG(`src/rng.ts`)로 교체 (구슬 순서·밀도·스킬·흔들기).
  파티클 같은 화면 장식은 그대로 `Math.random`.
- 물리 진행을 프레임이 아니라 **공유 시각** 기준으로 계산. 60fps든 30fps든 같은 스텝을 돈다.
- 스텝 크기와 구슬 정렬 시점을 프레임 루프 안으로 옮겨서 기기 성능이 결과에 섞이지 않게 함.
- 골인한 구슬 제거를 `setTimeout`(벽시계) 대신 시뮬레이션 시각 기준으로 변경.
- 늦게 접속해도 그 자리에서 밀린 경기를 따라잡아 합류한다 (프레임당 스텝 상한 안에서).

전송은 **1.5초 폴링**이다. SSE 로 만들었다가 Cloudflare 터널에서 응답 본문이 통째로 막히는 걸
확인하고 갈아엎었다. 시작 신호가 늦게 도착해도 각자 그 시점까지 따라잡으므로 결과는 같다.
덕분에 어떤 프록시·CDN 뒤에서도 동작하고, 서버 쪽 브로드캐스트 코드도 사라졌다.

## 실행

### 1. 웹으로 (어디서든)

```shell
yarn            # 최초 1회
yarn start      # 빌드 + 서버 실행 (= yarn build && node server.mjs)
```

띄우면 주소 두 개가 나온다.

```
관전자/참여자 : http://192.168.0.10:3000/
관리자        : http://localhost:3000/?key=3f9ac21b
```

- **관리자 주소**만 설정과 시작 버튼을 쓸 수 있다. 이 주소는 남에게 주지 말 것.
  (관리자 주소가 localhost 인 건 서버를 띄운 본인이 쓰는 주소이기 때문이다)
- 처음 띄우면 윈도우 방화벽이 접근 허용을 물어본다. **허용해야 다른 기기에서 들어올 수 있다.**
- 참여자·관전자는 앞의 주소로 들어오면 되고, 관리자가 시작하는 순간 같은 경기가 시작된다.
- 관리자 화면의 **참가 주소** 칸이나 옆의 `복사` 버튼을 누르면 공유용 주소가 복사된다.
  (클립보드가 막히는 환경에서는 주소가 전체 선택되므로 `Ctrl+C` 로 복사하면 된다)

옵션

```shell
PORT=8080 ADMIN_KEY=our-secret node server.mjs    # 포트·키 고정
```

- 방 나누기: 주소 뒤에 `?room=반이름` (관리자는 `?room=반이름&key=...`). 방마다 경기가 따로 돈다.

### 같은 와이파이 밖에서도 들어오게 하려면

LAN 주소(`192.168.x.x`)는 같은 네트워크 안에서만 열린다. 인터넷에 공개하려면 터널이 필요하다.

**exe 를 쓰면 메뉴에서 클릭 한 번이면 끝이다.** CLI 로 직접 할 때는 npm 패키지를 쓰면 된다.

```shell
npx untun tunnel http://localhost:3000    # -> https://xxx.trycloudflare.com
```

터널 주소를 앱이 참가 링크로 쓰게 하려면 그 주소를 알려준다.

```shell
PUBLIC_URL=https://xxx.trycloudflare.com node server.mjs
```

- 계정도 도메인도 필요 없다 (Cloudflare Quick Tunnel). 껐다 켜면 주소가 바뀐다.
- `untun` 은 이미 의존성에 들어있다. 최초 1회 cloudflared 바이너리를 자동으로 내려받는다.
- **HTTPS 라서 폰에서 PWA 설치와 클립보드 복사가 이 주소로만 제대로 된다.**
- ngrok, tailscale funnel, 그냥 서버에 올리기 등 무엇이든 상관없다. `PUBLIC_URL` 만 맞춰주면 된다.
- exe 를 쓰면 이 과정이 메뉴 클릭 한 번이다 (아래 참고).
- 고정 도메인이 필요하면 Cloudflare 계정 + named tunnel 을 쓰면 된다.

### 2. 관리자용 exe (설치 과정 없음)

```shell
yarn dist:exe        # release/ 에 portable exe 생성
```

exe 를 실행하면 서버가 같이 뜨고 관리자 화면이 바로 열린다. (설치 과정 없음)
처음 실행할 때 뜨는 방화벽 허용 창은 **허용**해야 참여자가 들어올 수 있다.

실행하면 **참가자를 어떻게 받을지 한 번 물어본다.**

| 선택 | 참가 주소 | 범위 |
|---|---|---|
| 인터넷에 공개 (도메인) | `https://....trycloudflare.com/` | 어디서든. 폰 앱 설치(PWA)도 가능 |
| 같은 와이파이만 (IP) | `http://192.168.x.x:3000/` | 같은 네트워크만. 외부 노출 없음 |

LAN 에는 도메인이라는 게 없어서 IP 로 나온다. 도메인은 터널을 열어야 생긴다.
나중에 메뉴의 `참가 주소 > 인터넷에 공개` 로도 바꿀 수 있고, 바꾸면 화면의 참가 주소도
자동으로 그 도메인으로 갱신된다.
창 위쪽 메뉴의 **참가 주소**(`Ctrl+Shift+C`) 또는 화면의 `참가 주소` 칸에서
참여자에게 줄 주소를 복사할 수 있다.
같은 와이파이에 있는 사람은 그 주소로 들어오면 끝.

**인터넷에 공개**하려면 같은 메뉴의 `인터넷에 공개 (cloudflared)` 를 누른다.
확인창에서 승인하면 `https://xxx.trycloudflare.com` 주소가 만들어져 클립보드에 복사되고,
화면의 참가 링크도 그 주소로 바뀐다. 앱을 끄면 터널도 같이 닫힌다.
별도 설치는 필요 없다 — `untun` 이 내장되어 있고 최초 1회만 cloudflared 를 내려받는다.

macOS(dmg)·Linux(AppImage) 는 `yarn dist:app`. 각 OS 에서 빌드해야 한다.

### 3. 앱으로 설치 (참여자·관전자)

서버가 HTTPS 로 떠 있으면 접속만 해도 설치할 수 있다.

- Android(Chrome)·데스크톱(Chrome·Edge): 화면 좌상단 **앱 설치** 버튼, 또는 주소창의 설치 아이콘
- iOS(Safari): 공유 -> 홈 화면에 추가

**진짜 `.apk` / `.msix` 파일**로 뽑아 배포하고 싶으면 서비스에 올린 뒤
[PWABuilder](https://www.pwabuilder.com) 에 주소를 넣으면 스토어 업로드용 패키지가 나온다.
(manifest 와 service worker 는 이미 준비되어 있다.)

### 공개할 때의 보안

인터넷에 열면 **주소를 아는 사람은 누구나 관전할 수 있다.** 그 전제 위에서 이렇게 막아뒀다.

| 항목 | 처리 |
|---|---|
| 시작·설정 권한 | 서버가 관리자 키로 검증한다. 키 없는 요청은 403. 관전자 UI 숨김은 화면 정리용일 뿐이다 |
| 관리자 키 | 128비트 무작위 (`ADMIN_KEY` 로 직접 지정 가능). 참가용 링크에는 절대 들어가지 않는다 |
| 화면 공유 대비 | 주소창의 `?key=` 는 접속 즉시 지워지고 sessionStorage 로 옮긴다. 탭을 닫으면 사라진다 |
| CSRF | 관리 API 는 `x-admin-key` 헤더를 요구한다. 쿠키 인증이 아니라서 다른 사이트가 대신 요청을 보낼 수 없다 |
| 파일 접근 | `dist/` 밖의 경로는 거부. 디렉터리 목록도 안 준다 |
| 자원 고갈 | 방 100개·방당 200접속 상한, 본문 64KB 상한. 빈 방은 자동 회수 |
| 데스크톱 앱 | `contextIsolation` 켜짐, Node 통합 꺼짐. 외부 링크는 앱 창이 아니라 시스템 브라우저로 열린다 |

주의할 것

- **참가자 이름은 링크를 아는 사람 모두에게 보인다.** 실명을 쓸 거면 공개 링크 대신 LAN 주소를 쓸 것.
- **관리자 주소(`?key=`)는 절대 공유하지 말 것.** 공유용은 `참가 주소` 메뉴 / 화면의 참가 링크 칸에 있는 것이다.
- 임시 터널 주소는 앱을 끄면 사라진다. 계속 열어둘 거면 고정 도메인 + 인증을 따로 두는 편이 낫다.
